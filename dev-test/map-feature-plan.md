# 地图诉求分析功能简化方案

## 1. 核心目标

本功能只新增一个“地图分析”界面，用中国地图作为入口，展示各城市居民留言诉求的热点情况。

核心交互只有两个：

```text
1. 鼠标指向某个城市：
   弹出小框，展示该城市群众最关心的排名前几的问题。

2. 点击某个城市：
   跳转到现有的“报告生成页面”，查看或生成该城市的大模型分析报告。
```

本阶段不新增单独的城市详情页，也不重新设计报告界面。报告仍复用已有的“报告生成”功能。

## 2. 页面入口

建议在顶部导航栏新增一个入口：

```text
数据概览 | 向数据提问 | 地图分析 | 报告生成 | 数据管理
```

点击“地图分析”进入新页面：

```text
/map
```

该页面主要展示中国地图。

## 3. 地图页面展示内容

地图页面的主体是中国地图，地图上展示城市点位或城市区域。

当前 Demo 阶段只有苏州市真实数据，因此可以先这样处理：

```text
苏州市：
显示为高亮城市或高亮点位。

其他城市：
显示为灰色、弱化状态，Tooltip 显示“暂无数据”。
```

后续如果接入更多城市数据，只需要在后端接口中补充城市数据，前端地图逻辑可以继续复用。

## 4. 鼠标悬浮 Tooltip

当鼠标放到某个城市上时，弹出小框。

Tooltip 内容建议控制在较小范围内，不做复杂详情页。

建议展示：

```text
城市名称
留言总量
回复率
平均回复耗时
群众最关心的问题 TOP 3 或 TOP 5
```

示例：

```text
苏州市

留言总量：10895
回复率：99.81%
平均回复耗时：94.5 小时

群众最关心的问题：
住房建设     ████████  2290
其他         ████████  2318
医疗卫生     ███       842
教育         ██        735
交通出行     ██        612

点击查看城市报告
```

Tooltip 里的热点问题可以用两种方式展示：

```text
文字排行
横向小柱形图
```

推荐优先做“文字 + 横向小柱形图”，视觉效果更直观。

## 5. 点击城市后的行为

点击城市后，不新增新的城市详情页，而是跳转到现有“报告生成页面”。

例如点击苏州市后跳转到：

```text
/reports?city=苏州市
```

如果现有报告页面当前只支持 `selected=report_id`，后续实现时可以考虑让报告页面支持城市参数：

```text
/reports?city=苏州市
```

进入报告页后，可以让用户在现有页面中：

```text
查看该城市已有报告
生成该城市新报告
下载报告
```

也就是说：

```text
地图负责选择城市
报告页面负责生成和展示报告
```

## 6. 推荐前端技术

推荐使用：

```text
ECharts + 中国地图 GeoJSON
```

原因：

```text
适合中国地图
支持 tooltip
支持点击事件
支持城市点位
支持颜色高亮
与当前 FastAPI + HTML 模板集成简单
```

当前阶段不需要 Mapbox、MapLibre 等更复杂地图框架。

## 7. 后端接口设计

本阶段只需要新增两个核心接口：

```text
GET /map
返回地图分析页面。

GET /api/map/overview
返回地图所需的城市聚合数据。
```

`/api/map/overview` 返回示例：

```json
{
  "cities": [
    {
      "province": "江苏省",
      "city": "苏州市",
      "lng": 120.5853,
      "lat": 31.2989,
      "total": 10895,
      "response_rate": 99.81,
      "average_response_hours": 94.5,
      "top_topics": [
        {"name": "其他", "count": 2318},
        {"name": "住房建设", "count": 2290},
        {"name": "医疗卫生", "count": 842},
        {"name": "教育", "count": 735},
        {"name": "交通出行", "count": 612}
      ],
      "report_url": "/reports?city=苏州市"
    }
  ]
}
```

前端拿到该接口数据后：

```text
1. 在地图上定位城市
2. 根据 total 控制点位大小或颜色
3. 根据 top_topics 生成 Tooltip
4. 点击城市后跳转 report_url
```

## 8. 数据来源

当前 Demo 阶段可以直接复用已有的统计逻辑。

例如：

```text
dashboard_stats(session, city="苏州市")
```

从中取出：

```text
total
response_rate
average_response_hours
topics TOP 5
```

后续接入更多城市时，可以逐步扩展为：

```text
遍历所有已导入城市
分别计算每个城市的统计数据
返回给地图页面
```

如果未来数据量很大，再考虑预聚合表或缓存。本阶段不需要提前实现复杂数据架构。

## 9. Demo 阶段落地方式

当前只有苏州市真实数据，所以 Demo 阶段建议：

```text
1. 新增“地图分析”导航入口
2. 新增 /map 页面
3. 加载中国地图
4. 在苏州市位置显示高亮点
5. 鼠标悬浮苏州市时显示 Tooltip
6. Tooltip 展示苏州市 TOP 问题
7. 点击苏州市跳转到现有报告生成页面
8. 其他城市显示暂无数据或不响应点击
```

这样可以满足当前展示需求，同时保留未来扩展空间。

## 10. 用户交互流程

完整流程如下：

```text
1. 用户进入“地图分析”页面
2. 页面展示中国地图
3. 用户鼠标移动到苏州市
4. 弹出 Tooltip，显示苏州市群众最关心的问题排行
5. 用户点击苏州市
6. 页面跳转到现有“报告生成页面”
7. 用户在报告页面查看或生成苏州市大模型报告
```

## 11. 视觉设计建议

地图页面建议保持简洁，不做复杂大屏。

推荐视觉风格：

```text
浅色背景
中国地图居中展示
苏州市高亮
无数据城市浅灰
Tooltip 使用白色小卡片
热点问题使用横向小柱形图
点击城市时有明显 hover 效果
```

Tooltip 不宜太大，控制在一屏内清晰可读。

## 12. 推荐开发顺序

建议按以下顺序实现：

```text
第一步：新增地图页面 /map
第二步：导航栏新增“地图分析”
第三步：接入 ECharts 中国地图
第四步：新增 /api/map/overview
第五步：返回苏州市真实统计数据
第六步：地图上高亮苏州市
第七步：实现鼠标悬浮 Tooltip
第八步：Tooltip 显示 TOP 问题排行和小柱形图
第九步：点击苏州市跳转到现有报告生成页面
第十步：后续再扩展更多城市数据
```

## 13. 最终简化方案

当前阶段只做：

```text
一个新地图页面
一个地图数据接口
苏州市真实数据高亮
Tooltip 展示群众最关心的问题 TOP 5
点击城市跳转现有报告生成页面
```

不做：

```text
新的城市详情页
复杂筛选器
右侧排行榜
新的报告展示界面
复杂缓存和聚合表
多层地图钻取
```

一句话总结：

```text
地图功能作为城市选择和热点预览入口即可；鼠标悬浮看热点问题，点击城市进入已有报告生成页面，不额外新建城市报告界面。
```
